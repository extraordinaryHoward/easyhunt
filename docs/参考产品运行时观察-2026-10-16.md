# 聘小助 v2.16.0 运行时观察（2026-10-16）

本文件记录授权使用已安装客户端时，在界面中直接观察到的行为。界面内容属于参考产品和登录账号；这里只记录产品结构，不保存候选人信息、聊天内容或账号凭据。与报告中“推断”的内容分开看待。

## 观察记录

| 编号 | 实际观察 | 对 Easyhunt 的影响 |
| --- | --- | --- |
| UI-01 | “打开浏览器”和项目右上角“还原浏览器”打开独立的“BOSS直聘 - 聘小助平台浏览器”窗口。主工作台保持可用，并在右上角显示带“还原/收起”按钮的页面预览。 | 浏览器与工作台分窗；保留小窗预览入口。 |
| UI-02 | 参考浏览器有平台标签、地址栏、后退/刷新、收藏及返回主窗口。BOSS 登录页面与工作台页面分开。 | Easyhunt 目前只有简易工具栏，后续可补足基本导航。 |
| UI-03 | 已登录 BOSS 的“职位管理”侧栏链接指向 `/web/chat/job/list`；实际职位卡片位于同域 iframe `/web/frame/job_v2/list?...`。界面显示“共 66 个职位 / 每页 20 个”，有数字分页按钮。 | 同步应读 iframe，并逐页读取；仅查顶层 DOM 或第一页会漏职位。 |
| UI-04 | 职位卡片展示职位名称、公司、城市、经验、学历、薪资和状态。状态包括“开放中”“待开放”“已关闭”。 | Easyhunt 的职位索引至少保留名称、城市和状态；同步过程不得点击“编辑/关闭/打开”。 |
| UI-05 | 项目有“简历列表、平台设置、人才画像、任务配置”四个页签。平台设置包含已同步职位、搜索/推荐/投递/复聊场景、搜索词顺序和筛选条件。 | 当前 Easyhunt 的配置页仍较浅，后续按实际使用频率逐项补齐。 |
| UI-06 | 新职位先选“工作流模式”或“agent 模式”；下一步进入 JD 来源选择，可“同步 JD”或“粘贴 JD”。 | Easyhunt 向导可重排为模式→JD 来源→画像确认。 |
| UI-07 | “寻访 SKILL”页说明本机 CLI/Skill 安装、人工接管能力，并每 5 秒显示最近 100 条本机操作回执。 | Easyhunt 的日志视图应继续保持本机可见；第三方动作需要授权与确认。 |

## 实现选择与未知

- `UI-03` 的 URL、iframe 和分页来自运行时界面；职位卡片的 CSS 类名没有原始证据。因此 Easyhunt 使用属性优先、文本校验的回退读取，并在代码中标记 `DESIGN-DECISION`。
- 尚未在参考产品中触发打招呼、收藏、分享、扣积分、删除职位或任务启动。这些动作可能影响账号、候选人或费用，不能把未观察到的结果写成事实。
- “新职位→下一步”会创建一个向导会话；已通过“上一步”返回，没有填写或发布 JD。
