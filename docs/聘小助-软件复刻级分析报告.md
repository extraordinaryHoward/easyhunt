## 0. 一页看懂（TL;DR）

聘小助 = **Electron 桌面端 + 独立 RPA 引擎 + 云服务 + Next.js 官网**，是一套「AI 招聘数字员工」。核心链路：

```
JD/已发布职位 → AI 生成人才画像 → 配置搜索词+筛选项（手动或 AI 自动迭代）
→ 内嵌浏览器(CDP)自动操作 BOSS直聘/猎聘/智联招聘
→ 采集简历 → 10 段处理流水线(清洗→结构化→标签→权重匹配→排序)
→ 匹配星级 + 三类分析(匹配/不匹配/待确认) → 自动打招呼
```

复刻要点：**RPA 引擎独立进程 + skill 插件化（每平台一个）+ 异步 operation 队列 + 三层存储（项目云端/简历本地/会话浏览器）+ LLM 服务端代理**。

**核心架构决策（复刻必须遵循）**：

1. **RPA 与 UI 解耦**：RPA 引擎是独立进程/模块，通过 localTransport 桥接。好处：可独立更新（`skill-download` 独立于 `desktop-download`）、可崩溃隔离。
2. **异步 operation 模式**：所有 RPA 操作 `POST /operations` → 返回 operation id → 轮询 `GET /operations/{id}` → 可 `POST /operations/{id}/cancel`。长任务（2-3 小时）的标准模式。
3. **人工接管点**：`POST /sessions/{ref}/control` 支持 pause/resume，实现「不抢鼠标」。
4. **三层存储**：项目数据云端；简历原文+附件本地（3 类目录可配置可迁移）；平台登录态在内嵌浏览器 + Cookie 导入。

## 3. 功能全集（含审核新增）

### 3.1 项目与职位管理
- 新建职位：同步 JD（平台已发布）/ 粘贴 JD；`jdSource` 四态 `t|m|l|s`
- 多平台并行；同职位多平台须同一岗位
- 全部职位（进行中/已归档）、近期职位；归档只读可取消归档
- 项目排队（FIFO，完成自动开下一个）
- 平台管理：同步已发布职位、按平台筛选、删本地记录、默认同步范围

### 3.2 人才画像
- JD → AI 推断画像（核心能力/经验/学历/地点）
- 画像版本管理（版本变更清空候选人）
- 对话式修改（自然语言改 JD/问进度）
- **画像三类结构（审核新增）**：`【硬性条件】hardConditions`、`【业务条件】businessConditions`、`【加分项】bonusItems`，每项含 `content` + `evidence`（证据数组）

### 3.3 双驾驶模式
| | 辅助驾驶 | 自动驾驶 |
|---|---|---|
| recruitmentMode | `manual`（工作流模式） | `target`（agent 模式，测试版） |
| 策略 | 用户设搜索词/筛选 | AI 自动设置+持续迭代 |
| 提示 | — | "agent 模式仍在测试，寻访效果可能不稳定" |

### 3.4 搜索与筛选引擎
- **场景配置**：每平台推荐页 + 搜索页，`sceneOrder` 可调，至少开一个
- **自动沟通模式（审核新增）** `sourceCommunication`：
  - `greeting`（打招呼）/ `contact_ta`（交换联系方式）/ `greeting_contact_ta`（两者，仅 boss）/ `none`
  - 每个场景可配 `minStars`（最低星级，默认 4）、`enabled`
  - 非 boss 平台：推荐页或搜索页任一开启即 `greeting`
- 搜索词自定义 + 进度（`completedKeywordCount / searchKeywordTargetCount`）
- 筛选目标：`targetCount`（默认 30，或 headcount）/ `targetMinStars`（默认 4）
- 快筛（20 积分）/ 初筛（40 积分）两级
- 页面质量反馈（"质量中等，建议翻页"）、广告关闭、硬性条件检查

### 3.5 简历处理流水线（审核新增，10 阶段）
```
接收需求(初始状态) → 准备采集(加载中) → 原始数据采集(重点细化)
→ 数据清洗过滤(处理中) → 结构化解析(处理中) → 智能标签提取(处理中)
→ 算法权重匹配(计算中) → 候选人排序筛选(优化中) → 结果整合生成(生成中)
→ 匹配完成(完成)
```
- 采集字段：简历信息、工作履历、技术栈标签、项目经历、求职意向、活跃时间、薪资期望
- 清洗：剔重复、滤静默账号、筛过期求职者
- 结构化：学历/工作年限/技术能力/跳槽频率/项目行业经验
- 标签：后端开发/框架熟练度/数据库/中间件/工程能力等技能维度
- 权重匹配：多维比对职位要求与人才匹配度

### 3.6 简历分析与评分（审核新增）
- 星级评分：1-5 星，`AI 简历分析评分：N 星`
- **三类分析组**：`matched`（匹配项）/ `mismatched`（不匹配项）/ `pending`（待确认项），每项含 `content` + `evidence`
- 快筛淘汰结果单独展示（"快筛结果不相关的放到这里"）

### 3.7 候选人管理
- 列表分页（32 位 hex 游标）、详情、匹配分析
- 操作：收藏 / 打招呼 / 分享（均需 `confirmed` 确认参数）
- HR 决策：`PROMOTED / CONSIDERING / REJECTED` + 原因；批量（`resumes/decision`）
- 联系方式同步：未确认交换微信/电话不同步（合规开关）
- 候选人身份校验

### 3.8 简历分享协作（审核新增，完整模型）
- `resume/{id}/shares` 增删查；`share-users/lookup` 查找被分享人
- 权限：`READ` / `EDIT`
- 受众：`recipients`（指定人，≤50 人）/ `all`（所有人）
- 内容：`{ sourceText: string(≥1), document: nullable }`
- 手机号校验 `/^1[3-9]\d{9}$/`
- 分享链接生成 + 复制

### 3.9 对话系统（审核新增）
- `chat/conversations`（title, projectId, withGreeting, jobPublishStatus）
- 消息流 + `workflowEvents` + `workflowCursor`（工作流事件游标）+ `feedbackRatings`（反馈评分）
- `session-boundaries`（会话边界）、`active-workflow/cancel`（取消激活工作流）、`background-tasks/{id}/cancel`（取消后台任务）
- 消息反馈 `chat/messages/{id}/feedback`
- 自然语言交互：改 JD、问状态、补充需求

### 3.10 内嵌浏览器
- 每平台独立 BrowserView + 完整浏览器外壳（地址栏/标签/收藏/下载/页内查找/缩放）
- Cookie 导入（Chrome/Edge 用户）
- 平台锁定；`session.pause/resume` 人工接管；单设备登录限制

### 3.11 账户计费
- 登录（短信验证码 `send-code`）、token 刷新（`auth/refresh`）
- 积分（快筛 20 / 初筛 40）、套餐（159/499/1799 月）、充值卡（2 年）、邀请返利（100 元）
- 会员「聘小助 GO 权益」、首单优惠（`billing/first-order-offer`）
- 积分不足自动停任务；明细导出

### 3.12 系统功能
- 新手引导（driver.js 分步引导）、可重开
- 自动更新（桌面 + skill 双通道）、RPA 模块版本查询
- 启动状态/日志、诊断上报、数据迁移、托盘后台运行、任务授权可撤销

### 3.13 授权协议（审核新增）
- **第三方招聘平台委托代理操作授权**：iframe 展示完整协议正文（`sandbox: allow-scripts`），需「同意并签署」按钮，含手机号绑定校验
- 授权可撤销（`settings:revoke-task-authorization`）

## 6. 数据模型

### 6.1 招聘配置 recruitment config
```ts
{
  recruitmentMode: 'manual' | 'target',   // 辅助驾驶/自动驾驶
  jdSource: 't' | 'm' | 'l' | 's',        // JD 来源四态
  targetCount: number,        // 默认 30，或 headcount
  targetMinStars: number,     // 默认 4，1-5
  maxResumeCountPerKeyword: number,   // 单组搜索词最多快筛份数
  maxRecommendResumeCount: number,    // 推荐页最多快筛份数
  sourceCommunication: {
    recommend: { enabled: boolean, minStars: number },
    search:    { enabled: boolean, minStars: number },
    sceneOrder?: ['search'|'recommend', ...],
    platformPaused?: boolean,
    newGreeting?: {...}
  }
}
```

### 6.2 筛选项 schema（138 个 code）
`{ key, label, type: 'multi'|'range'|'any', options, valueShape: 'wrapped', optionControl: 'buttons' }`
分类：年龄（单岁+区间）、学历（含 985/211/双一流/QS100/500/海外）、经验年限、求职状态（应届/在职/离职/到岗时间）、活跃度、跳槽频率、语言、性别。完整清单见 `界面文案全集.txt`。

### 6.3 简历（zod）
```ts
Resume = {
  name(1-100), phone, email, wechat,   // 联系方式含"未确认交换"合规开关
  expectedCity?, expectedTitle?,
  expectedSalary?: { min, max, unit:'K/月', months? },
  expectedSalaryText?, skills(≥1),
  workExperiences[], educationExperiences[],
  // 解析源: 公司性质/规模/城市/学历/工作年限/年龄/所在城市/求职状态/行业
}
```

### 6.4 决策与分享
```ts
Decision = { decisionStatus?: 'PROMOTED'|'CONSIDERING'|'REJECTED', decisionReason?(≤500) }
// 批量 { resumeIds(1-100), ...Decision }
Share = { audience?: 'recipients'|'all', recipients?: [{userId(≤32), permission:'READ'|'EDIT'}](≤50), content:{sourceText(≥1), document?} }
```

### 6.5 任务状态机
`待创建 → 创建中 → 待确认 → 进行中 → 已完成 | 已停止 | 执行失败`；`已归档`（终态只读）；`等待确认`（人工介入点）。

## 7. 核心业务流程

### 7.1 首次引导
登录 → 新手引导（driver.js）→ 新职位 →〔同步/粘贴 JD〕→ 选平台 → 选驾驶模式 → 确认画像 → 平台授权（登录窗 2 分钟）→ 开始招聘 → 简历列表。

### 7.2 授权模型
```
选平台 → 弹登录窗 → 用户登录(≤2min) → 授权完成 → 签发 task-authorization 令牌
→ 可随时撤销（运行中任务停止）→ 平台账号他处登录 → 任务暂停报错
```

### 7.3 任务执行（辅助驾驶/manual）
```
task.create(input-file) → browser.open → search.fields→get→set→apply
→ candidates.list → 快筛(20分)→初筛(40分)→星级
→ 达标/搜索词完成 → 任务完成；积分不足自动停；翻页/关广告
```

### 7.4 自动驾驶（target/agent）
JD/画像 → AI 生成搜索词+筛选项 → 执行 → 分析不同搜索词组合表现 → 自我迭代 → 优化画像 → 达标停止。

### 7.5 打招呼
仅推荐页绑定职位后 → candidates.greet(candidate-ref, job-ref, confirmed, message-mode)，前置用户明确授权。

```
│   ├── api/                 # 31 条命令 HTTP API
│   ├── cdp/                 # CDP 控制器
│   ├── skills/              # boss/liepin/zhaopin 插件
│   ├── tasks/               # 任务状态机
│   └── operations/          # 异步操作队列
├── server/                  # 云服务（REST API 61 条）
│   ├── auth/ billing/ chat/ invitations/
│   ├── project/ resume/ user/
│   └── llm/                 # LLM 代理（DeepSeek）
└── web/                     # Next.js 官网 + 分发
```

### 10.2 MVP 六步
1. Electron 壳 + 内嵌浏览器 + CDP 点击/读取（先 boss 单平台）
2. 手动配置搜索词/筛选项 → 工作流模式 → 列表抓取 → 简历解析（正则→LLM）
3. 本地积分 + 本地项目存储
4. LLM 服务端代理 → AI 画像 + 匹配打分 + 三类分析组
5. 补 liepin/zhaopin skill 插件
6. 补账户/支付/邀请/分享协作 → agent 模式

### 10.3 关键实现注意
- **RPA 操作必须异步化**：operation id + 轮询 + 取消，长任务不能阻塞 UI
- **skill 插件化**：平台页面 DOM 会变，独立更新通道是关键
- **人工接管点**：pause/resume 是「不抢鼠标」的核心
- **三层存储边界清晰**：简历本地（隐私卖点）、项目云端（同步）、会话浏览器（登录态）
- **敏感动作双确认**：`confirmed` 参数 + 界面确认 + 授权协议签署
- **LLM 可替换**：baseUrl/apiKey 配置化，默认 DeepSeek

## 11. 合规与风险

1. **平台协议**：自动化操作招聘平台可能违反其用户协议（原版亦承认"无法 100% 保证安全，建议合理设置频率，预留备用账号"）
2. **授权边界**：所有敏感动作（打招呼/收藏/分享）强制 `confirmed` + 界面明示授权 + 签署委托代理协议
3. **个人信息保护**：简历含敏感信息，本地存储、传输加密、最小化上云、联系方式交换需确认（符合《个人信息保护法》）
4. **反爬对抗**：平台更新 DOM/加强风控，skill 插件化 + 独立更新对冲
5. **单设备登录**：平台互踢导致任务中断，需断点恢复
