# Easyhunt 参考产品功能差距与改造清单（2026-10-16）

## 范围与证据

- **直接观察**：在已安装的聘小助 v2.16.0 客户端中查看新职位向导、已有项目、候选人详情、平台设置、任务动态、平台管理、账户菜单和系统设置。只记录结构与交互，不保存候选人原文、个人资料或登录信息。
- **已有观察**：见《参考产品运行时观察-2026-10-16.md》，包含独立浏览器、小窗预览和 BOSS 职位 iframe 分页。
- **规格推断**：见《聘小助-软件复刻级分析报告.md》。报告中的推断不能当作运行时事实。
- **Easyhunt 对照**：以本仓库当前 `user-webapp/src/App.tsx`、`desktop/src/main.ts`、`rpa-engine/src` 和 `server/src` 为准。这里是代码能力盘点，不等于已在真实 BOSS 账号验证。

## 核心结论

Easyhunt 已有项目、简历索引、画像、独立 BOSS 浏览器、授权门槛和 RPA API 骨架，但关键路径仍有断点：**已发布职位同步 → 从职位获取 JD → 配置搜索 → 启动任务 → 持续展示可解释的进度 → 本地简历详情与决策**。优先修通这条链路，比先补账户、积分或其他平台的静态页面更有价值。

| 优先级 | 参考产品直接观察 | Easyhunt 当前状态 | 要改造的功能与验收方式 |
| --- | --- | --- | --- |

| P0 | 平台管理列出职位、城市、状态、最近同步；可配置参与同步的平台。BOSS 职位页为 iframe 分页。 | 有同步入口、索引表和 BOSS DOM 读取；用户此前反复遇到同步失败，最新版仅通过模拟 iframe 测试。 | 完成真实账号端到端同步验收：登录后同步、所有页去重、状态映射、再次同步幂等；显示已读数量、失败页和可重试原因。同步范围必须影响实际请求。 |

## 建议实施顺序

1. **打通 BOSS 首次使用**：平台登录状态、真实职位同步、JD 同步/粘贴、项目绑定职位。先解决用户当前无法同步的问题。
2. **补全任务可见性**：任务事件、断点恢复、失败原因、人工接管、小窗稳定性。
3. **补全结果工作台**：统计口径、候选人详情、画像版本、决策与本地原文证据。
4. **扩展平台设置**：BOSS 筛选 schema 与场景排序，再逐个平台做能力验证。
5. **完善协作与系统功能**：分享期限、权限、设置闭环、Skill 接入说明。

## 尚未验证

- 没有在参考产品中启动新任务、发送打招呼、收藏、分享、充值、签署协议或删除职位；这些动作会改变账号、候选人或费用状态。
- 没有确认参考产品每个筛选项如何映射到 BOSS DOM，也没有验证猎聘/智联的真实自动化流程。
- 本次未在 Easyhunt 安装包上再次使用真实 BOSS 账号完成同步；最新修复的测试只模拟了 iframe 重建。

## 产品边界

目标是复刻**信息架构、交互路径和用户可验证的行为**。Easyhunt 保持自己的名称、图标、文案及视觉系统；不复制参考产品的专有素材或未经证实的内部实现。第三方操作仍需用户授权、平台协议确认、频率限制和人工接管；敏感动作在引擎层确认。简历默认本地，分享时才按明确范围上传选定内容。
